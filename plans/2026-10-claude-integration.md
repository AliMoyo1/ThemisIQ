# Claude worktree integration, 22 October 2026

This branch starts from `fda8738964a3b492ffe3dc7543608b7db26a5827` on `master`. The active Claude worktrees start from older commits and remain untouched. A change in one of those worktrees is not considered integrated merely because its plan says it passed checks there.

## Integrated in this branch

- Privacy settings isolation: `/sentinel/api/settings` now reads only Privacy-owned fields and rejects all other write keys. This prevents the Privacy capability from reading mail credentials or changing `ai.policy.org*` approval records in the shared `settings` table. A batch of permitted fields commits together.
- Operations Risk AIMS scope: brought in the assessment, risk and control-link read/write guards and business-unit input checks from `great-jemison-18a029`. These use the assessment's unit for child records and mask missing and foreign IDs alike.
- Privacy DPIA form: merged the stored description, mitigations, owner and due date from `suspicious-swartz-8c47fe`. Added the nullable date migration and strict date parsing. Kept the newer template's quote escaping, safe URL handling and delegated event handlers from `master` instead of replacing it with the older worktree copy.
- Shared report kit: ported the PDF, DOCX, XLSX and print renderers and the ARIA, BCM, ERM, GRID, ORM, Privacy and platform report adapters from `sad-albattani-5255ea`. Three-way merged the 26 non-conflicting tracked files, then reconciled Evidence download naming, the Reports page security changes and the AIMS routes by hand. Preserved the current Evidence conversion worker and Privacy settings isolation. Regenerated the capability inventory from this branch's registered routes. This is code integration, not a verified release.
- Record documents: ported the DPIA, continuity plan and AI impact assessment PDF/XLSX adapters from `kind-cannon-4d360f`. The exports use each record's scoped read, log the download and list accessible Vault proof and connected records. Added safe links in all four report renderers, the three document actions, and the BCM plan guards for detail, review, activation, update and delete. The plan detail's evidence list now follows Evidence Vault scope as well. Regenerated the route inventory with 1,132 routes after the profile endpoints were added. The source worktree's verification does not apply to this integrated branch.
- DPIA form repair: the privacy drawer now saves processing operations, necessity and proportionality separately, as well as its description, owner, due date and mitigations. The displayed risk comes from the assessor's overall rating; the dashboard no longer treats a database default as a rating. Completion emits an escalation only on the first transition into a completed state and uses the residual rating when present. Previously unrated rows remain explicitly unrated.
- Regulator record profiles: a single profile definition now supplies supplementary RoPA, DPIA and internal AI impact assessment fields to the forms, validation, readiness gaps and record exports. The RoPA workbook separates controller and processor activities, includes the extended fields and missing-answer sheet, and the PDF now includes **every scoped activity and detailed dossier entry**, with no 60-row or million-row ceiling. DPIA and AI impact exports include their recorded supplementary answers and gaps. The jurisdiction dropdown uses the profile registry; legal-basis choices come from that jurisdiction's profile. The legal wording stays marked researched/unapproved or unverified, and the AI assessment is marked as an internal template. No automatic legal conclusion or independent AI approval is implied by completeness.
- AIMS unit scoping: assessments default to the writer's unit, cannot be placed in an unassigned or inactive unit, and only a super admin can create an organization-wide assessment. Risk, linked-control and aggregation reads follow the assessment's unit. Custom control catalogue entries and link counts follow the caller's scope; link counts and delete protection include both direct risk references and control-link references. Writers cannot link a unit-specific control to an assessment in another unit. Historical cross-unit catalogue references are masked on risk and aggregation reads; moving an assessment with conflicting linked controls is refused until reconciled.
- Continuity plans created in the app now inherit the author's business unit for access control. The typed process or unit owner is separate from that security owner and need not be a platform user. Historical plans with no unit remain organization-wide pending review; no author unit is inferred retroactively.
- Generated DPIA, AI impact and continuity plan PDF/XLSX downloads now file a pending-review Vault artifact linked to their source. A semantic content hash ignores the new rendering timestamp and downloader, so repeat generation reuses the current artifact. Changed content creates a version; the previous two appear in the Vault's generated history view. Older copies are archived with their bytes and audit history retained because no deletion or legal-hold schedule has been approved. Generated items cannot be manually replaced, edited, archived, restored or deleted, even in bulk; their source link cannot be removed. A failed Vault filing fails the export rather than claiming it was retained.
- The Vault now offers permission-filtered virtual folders for Audits, Incidents, Privacy records, Continuity plans, AI assessments, Reports by type, Policies and Generated records. Audit, incident and other source folders page through named records the viewer may open. These are views over the same artifacts and links, not duplicated files. The supplied React folder design was adapted to the existing Jinja/JavaScript stack as keyboard-usable, reduced-motion glass folder cards.
- Case report proof rows and the GRID operational audit report now link to currently accessible Vault documents using the configured application origin. The audit includes canonical files linked to the audit, its controls and its findings; files outside the reader's Vault scope are excluded.

## Product improvements proposed for review, not built

1. Give every figure an explainer that opens its exact source list, scope, as-of time and counting rule. A board member can see the number; a reviewer can trace it without recreating the query. Use the same source contract in dashboards and exports.
2. Make a report's connected records and Vault files a permission-filtered evidence index. Store source record IDs and file versions with the frozen run, then display the current state separately so a later file replacement never rewrites the historical claim. Begin with the Case and Audit reports already planned.
3. Make AI narrative discrepancies a review task: show the precise unsupported sentence, the figure it conflicts with and the source calculation. Do not let a narrative be signed off without either correction or a recorded reviewer exception.
4. Add a data-quality queue for missing owner, stale evidence, unmeasured control, overdue review and unknown jurisdiction wording. Link each item to an owner and its editing screen; keep it separate from the underlying risk score.
5. For large registers and evidence packs, use bounded background generation with progress, expiration and an audit record instead of holding a web request open. Preserve the current scope snapshot and permissions at generation time.
6. Make board and operational views of a saved run share one frozen data snapshot. The short view should foreground decisions and movement; the detailed view should expose methods, exceptions and source records. The current kit's `tier` field provides the starting point.

### A connected specialist workflow across the active work

These are proposed refinements to the existing module and worktree plans, not additional completed features. Build them around the canonical records already used by the modules; do not create another document store or a second request queue.

For each row, first inspect whether the linked source record and ownership rule already exist in the module plans. Start with the work list and evidence readiness; both directly improve navigation and prevent the Vault from becoming a disconnected file grid. Defer invitations and background report generation until their volume and authorization rules are established.
